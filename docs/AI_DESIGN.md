# 제국의 투쟁 전략 AI 설계안

작성일: 2026-09-10

상태: 아래 원래 설계를 바탕으로 전략 모드를 구현했다. 구현 방식과 실제 검증 결과는 [AI 구현·학습 안내](AI_IMPLEMENTATION.md)를 우선한다. 제안했던 200판 평가는 아직 수행하지 않았다.

## 1. 목표와 사용자 선택

현재 게임에서는 영국·프랑스의 반대편을 맡는 기본 AI와 플레이할 수 있다. 이번 설계 목표는 같은 규칙과 비공개 정보 제한 안에서 승리에 기여하는 행동을 더 잘 선택하는 상대다.

사용자는 빠른 진행보다 깊은 계산을 선호하며, AI가 한 행동 라운드를 결정하는 데 10~30초 정도 기다릴 수 있다고 답했다. 이 시간은 개별 공간 클릭마다 부여하지 않고 라운드 전체의 계획 예산으로 사용한다. 기본 목표를 20초, 상한을 30초로 두는 안을 제안한다. 실제 처리량과 중단 지연은 구현 후 이 PC에서 측정한다.

## 2. 지금 AI가 실제로 하는 일

2026-09-10 강화 작업 전 기본 AI를 검토한 기록이다. 이 코드는 비교 기준인 `scripts/ai/baseline_ai.gd`에 보존했다.

| 결정 | 현재 처리 | 개선할 점 |
|---|---|---|
| 투자 타일 | 주요 행동점수 × 3, 이벤트 표식 +2, 전쟁 준비 +1 등을 합산 | 타일을 고른 뒤 가능한 이벤트·주요·보조 행동 묶음의 결과를 평가 |
| 지도 행동 | 빈 공간 +5, 기본 비용 감점, 위신 +4, 동맹 +3, 수요 상품 +3 | 실제 지출 비용과 득점 우위의 변화, 다음 전쟁과 연결 상태를 평가 |
| 이벤트 | 사용 가능한 카드 중 보너스 조건을 만족하는 카드를 우선 | 지금 사용·보관·다른 카드 사용의 기대 결과를 비교 |
| 내각 선택 | 카드별 고정 가중치와 현재 손패 키워드 가산점 | 내각 두 장의 조합, 지도 상황, 시대·전쟁 시점과 손패를 함께 평가 |
| 내각 공개 | 자기 라운드에서 공개 가능한 선택 내각을 미리 공개 | 공개 효과와 비공개 유지의 이점을 비교 |
| 손패 정리 | 일반 AI 경로에서 마지막 세 장을 유지 | 미래 사용 가능성·보너스·내각 조합을 평가해 남길 세 장 선택 |
| 선공 선택 | 자신이 주도권을 가지면 자신을 선공으로 선택 | 투자 타일 선점과 후공 대응의 가치 비교 |
| 전쟁 선택 | 여러 자동 선택에서 첫 번째 합법 선택지 사용 | 전장 보상·정복 이후 득점·양도 거부 비용 등을 비교 |

주요 코드: `godot_project/scripts/autoload/ai_controller.gd`, `game_manager.gd`, `war_flow.gd`.

기존 284개 검사와 12판 완주 기록은 처리 경로·규칙·진행의 검증 자료다. 숙련자 대비 승률이나 전략적 강도를 측정한 자료는 아니다. 현재 수준을 고수급이라고 부를 근거는 없다.

## 3. 무엇을 잘하는 AI로 만들 것인가

공간에 고정 점수를 매기는 대신 행동 전후의 이득을 비교한다.

예를 들어 어떤 수요 상품 시장 수가 나 2개, 상대 2개일 때 추가 시장 하나로 단독 우위가 생긴다. 다른 상품에서 이미 충분한 우위를 가지고 있다면 시장 하나를 더 얻어도 이번 득점의 변화는 작을 수 있다. AI는 두 행동의 실제 비용과 상대가 다시 뒤집을 가능성까지 비교해야 한다. 이 예의 숫자는 사고방식을 설명하기 위한 것이며 특정 저장 상태의 분석 결과는 아니다.

평가 요소는 다음과 같다.

- 승리·패배: 승점 자동 승리, 수요·지역 독점 조건, 최종 득점을 최우선으로 다룬다. 일반 자원 가산점으로 확정 승패를 뒤집지 않는다.
- 세계 수요: 상품별 실제 보상, 우위·동률의 전환, 상대의 재탈환 가능성을 본다.
- 지역: 해당 턴 보상의 필요한 격차, 위신과 관련 내각 효과를 함께 본다.
- 전쟁: 다음 전쟁까지 남은 시간, 전장별 기대 보상과 정복 가치, 공개 전력과 자신의 타일 정보를 이용한다.
- 자원: 가용 채무, 조약점수, 남은 지출 기회, 함대 위치·건조·귀환, 행동점수의 용도 제한을 평가한다.
- 카드: 손패의 현재·다음 시대 활용 가능성, 이벤트와 내각의 결합, 카드를 뽑는 행동의 기회비용을 비교한다.
- 위치: 시장 연결, 고립 위험, 요새·함대·이점 접근, 상대의 싼 반격 가능성을 평가한다.

전체 점수와 ‘점수 대비 지출 효율’을 같이 본다. 단순히 이득/비용만 최대화하면 비싸더라도 즉시 승리하는 행동을 놓칠 수 있으므로 효율 비율은 후보 정렬용 보조 정보로 사용한다.

## 4. 구현 구조

```text
허용된 관측 정보
    ↓
합법 행동 후보 생성
    ↓
투자·이벤트·주요·보조 행동 계획 구성
    ↓
독립 시뮬레이션에서 후보와 상대 대응 비교
    ↓
시간 예산 안에서 가장 좋은 합법 계획 선택
    ↓
실제 게임에서 합법성 재확인 후 실행
```

### 관측 정보

AI에는 공개 보드·자원·공개 기록과 자기 손패·내각·자기 전쟁 타일만 전달한다. 상대 비공개 손패·내각·전쟁 타일의 실제 내용, 실제 뽑기 더미 순서와 실제 게임 난수 상태를 탐색 입력으로 전달하지 않는다.

모르는 정보는 공개 이력과 카드·타일 구성에 모순되지 않는 여러 가능한 상태로 추정한다. 자기 손에 있는 카드가 상대 손에도 나타나거나 이미 제거한 카드가 다시 등장하는 식의 잘못된 추정을 막아야 한다. 상대의 가상 판단 역시 그 상대가 알 수 있는 정보만 이용하게 한다.

Information Set Monte Carlo Tree Search는 비공개 정보와 불확실성을 가진 게임을 다루는 탐색 계열이다. 이 프로젝트에서는 그 정보 집합 관점을 후보로 삼는다. 알고리즘 이름만 적용했다고 강한 AI나 최적 전략이 보장되는 것은 아니다. [Cowling·Powley·Whitehouse, 2012](https://pure.york.ac.uk/portal/en/publications/information-set-monte-carlo-tree-search/)

### 행동 후보와 라운드 계획

투자 선택과 공간 클릭을 따로 최적화하면 연계가 끊긴다. 각 투자 후보에 대해 이벤트 사용·생략, 허용된 내각 공개·능력 사용, 주요·보조·이벤트 점수의 지출 순서를 하나의 계획으로 비교한다.

후보에는 함대 건조·배치·이동, 요새, 분쟁 제거, 전쟁 준비, 외교 카드 뽑기, 채무·조약 보충, 능력·이점, 패스와 라운드 종료를 포함한다. 모든 가능한 순서를 무작정 펼치지 않고, 빠른 평가로 유망한 후보를 추린 뒤 자세히 비교한다. 반드시 살아남겨야 하는 즉시 승리·패배 방지 행동은 일반 후보 절약 규칙보다 우선한다.

첫 단계는 평가 함수와 제한된 라운드 계획 비교다. 다음 단계에서 상대의 다음 행동 라운드와 다음 득점·전쟁 경계까지의 제한된 모의 진행을 붙인다. 미래 전체 게임을 매번 끝까지 계산할 수 있다고 가정하지 않는다.

### 실제 게임과 분리된 시뮬레이션

현재 규칙은 Autoload와 신호에 연결되어 있고, 저장 복원도 전역 상태를 바꾸고 일부 신호를 발생시킨다. `SaveLoad._deserialize()`를 실제 게임에서 수천 번 호출해 탐색하면 화면·기록·공개 상태·난수에 부작용을 줄 수 있다. 저장 그래프의 존재가 곧 독립 탐색 엔진의 완성을 뜻하지 않는다.

규칙의 판정·상태 전이 부분을 공통 코어로 분리하여 실제 게임과 시뮬레이터가 같은 계산을 쓰도록 한다. 탐색은 독립 상태와 독립 난수를 사용하고 UI 신호, 저장 파일, 행동 기록을 발생시키지 않는다. 탐색용 규칙을 별도로 복사해 유지하는 방식을 피한다.

화면은 계속 반응해야 한다. 분리된 데이터만 다루는 작업 또는 프레임별로 나누는 작업으로 계산하며, Godot 화면 노드나 전역 게임 상태를 다른 실행 흐름에서 직접 변경하지 않는다.

### 시간과 다시 계산하기

정해진 후보 수를 모두 처리할 때까지 기다리는 대신 경과 시간을 보고 중단한다. 10~30초는 라운드 전체 계획과 필요할 때의 재계산에 나누어 쓴다. 제한 시간에는 현재까지 가장 좋은 합법 계획을 사용한다. 간단한 강제 선택은 일찍 끝낼 수 있다.

숨겨진 새 카드·타일을 실제로 뽑거나 상대가 응답해서 계획의 전제가 바뀌면 남은 시간 안에서 재계산한다. 메뉴 이동·새 게임·불러오기 때는 기존 탐색을 취소하며, 예전 상태에서 계산한 결과가 새 판에 적용되지 않도록 상태 버전을 대조한다.

## 5. 강해졌는지 확인하는 방법

1. 현재 AI를 비교 기준으로 보존한다. 개선판과 같은 초기 조건에서 진영을 바꾼 짝 대결을 수행한다.
2. 개발에 사용한 시드와 최종 평가 시드를 분리한다. 특정 카드 순서에만 맞춘 개선을 방지한다.
3. 최초 평가 묶음으로 100개 시드의 진영 교대 200판을 제안한다. 이는 미실행 계획이며, 시간·승률의 안정성을 보고 평가량을 조정한다.
4. 전체 승률뿐 아니라 영국·프랑스별 결과, 승점 차이, 생각 시간의 중앙값·상위 구간, 멈춤·불법 행동·남긴 점수의 원인을 기록한다. 점수를 적게 남긴 사실만으로 잘했다고 평가하지 않는다.
5. 전략 상황 문제를 만든다. 수요 동률을 우위로 바꾸기, 독점 패배 방지, 전쟁 직전 필요한 보강, 의미 없는 추가 점유보다 유효한 보상 얻기 등을 확인한다.
6. 상대의 비공개 내용만 바꾼 같은 관측 상태에서는 같은 AI 난수로 같은 결정을 하는지 검사한다. 탐색 전후 실제 판·실제 난수·저장·공개 상태가 바뀌지 않는지도 확인한다.
7. 실제 사람 플레이로 단조로운 반복, 지나친 채무, 무의미한 내각 공개와 전쟁 선택을 검토한다. 기존 AI를 이긴 것과 숙련자를 상대할 수준인 것은 구분한다.

승률 목표 숫자는 아직 확정하지 않았다. 일단 현재 AI보다 일관되게 개선되는지를 진영별 성적과 결과의 불확실성까지 보고 판단한다. 이후 전략 문제와 사람 플레이 결과를 합쳐 난이도 이름을 정한다.

## 6. 학습용 설명

AI가 선택한 이유를 선택적으로 보여 줄 수 있다. 예를 들어 ‘이 시장을 얻으면 모피 시장이 동률에서 우위로 바뀝니다’ 또는 ‘이번 전쟁의 유럽 전장에 보강 가치가 큽니다’처럼 실제 평가에 사용한 근거를 표시한다.

비공개 손패·타일을 근거로 한 상세 설명은 대전 중 인간에게 보여 주지 않는다. 공개 정보로 설명 가능한 부분만 즉시 표시하고, 자기 비공개 정보가 담긴 분석은 해당 정보가 공개되거나 게임이 끝난 뒤 별도 복기에서 다룬다. 표시 문구는 한국어·영어로 관리한다.

## 7. 개발 순서와 현재 상태

| 단계 | 산출물 | 상태 |
|---|---|---|
| 현재 AI 검토 | 고정 평가·첫 선택 경로와 검증 한계 확인 | 완료 |
| 강화 설계 | 사용자 10~30초 선호, 평가·계획·정보·검증 구조 | 이 문서로 정리 |
| 1차 강화 | 보상 변화 평가, 내각 조합·손패·전쟁 선택, 기준 AI와 비교 | 구현·자동 대결 검증 |
| 탐색 기반 강화 | 독립 실행 환경·관찰 모델·시간 제한 계획 탐색 | 같은 규칙 엔진을 별도 프로세스에서 실행 |
| 평가와 제공 | 진영 교대 대결, 생각 중 표시·중단·저장 재개 | 구현·자동 검증; 숙련자 평가와 상세 복기는 후속 |

강화학습은 후속 선택지다. 독립 시뮬레이션과 평가 환경이 마련된 뒤 검토한다. 게임 탐색·강화학습 환경의 참고 구조로 OpenSpiel을 살펴볼 수 있지만, 이 게임을 바로 강하게 플레이하는 기성 AI가 제공된다는 뜻은 아니다. [OpenSpiel 논문](https://arxiv.org/abs/1908.09453)
